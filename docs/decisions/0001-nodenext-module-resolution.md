# 0001 — `nodenext` module resolution over `bundler`

We chose `"module": "nodenext"` with `"moduleResolution": "nodenext"` in `tsconfig.base.json` over `"moduleResolution": "bundler"`. TypeScript 7 removed the old `node`/`node10` resolution, so we had to pick a replacement. Both options type-check `@cda/domain` today, but the API runs directly on Node as CommonJS without a bundler. `nodenext` follows Node's actual rules: it respects each package's `"type"`, its `exports` maps and the file-extension requirements for ES modules. Code that type-checks will therefore also resolve at runtime. `bundler` is more lenient and could hide imports that only work through a bundler. The cost is that if a package ever switches to `"type": "module"`, its relative imports must include file extensions.
