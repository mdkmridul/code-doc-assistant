# 0005 — Prisma for schema and data access, with a hand-written migration for search columns

The API uses Prisma 7 (`prisma-client` generator, CommonJS output, `@prisma/adapter-pg`) for every table, and `PrismaService` replaces the plain `pg` pool from ADR 0002. We did not keep raw SQL everywhere or adopt a query builder. Prisma gives us typed models, generated migrations and drift detection for the ordinary tables, which make up most of the schema. Prisma cannot express pgvector columns, `GENERATED ALWAYS ... STORED` columns or HNSW indexes. So the init migration is Prisma-generated, and `*_chunk_search_columns` is written by hand: it adds `CREATE EXTENSION vector`, `chunks.embedding`, the generated `chunks.search_vector`, and their HNSW and GIN indexes. Those columns are still declared in `schema.prisma`, as `Unsupported(...)` with the exact `dbgenerated(...)` expression and both `@@index` entries. Without them, Prisma's diff would try to drop the indexes and the generated expression. `prisma migrate diff --from-config-datasource --to-schema prisma/schema.prisma` must report an empty migration. Full-text search uses the `simple` configuration instead of `english`, so identifiers like `handlers` or `getUserById` are indexed exactly as written, without stemming or stop-word removal. We pinned Prisma to 7.10.1: npm's `latest` tag points at an 8.0 release candidate that needs Node ≥ 22.18.
