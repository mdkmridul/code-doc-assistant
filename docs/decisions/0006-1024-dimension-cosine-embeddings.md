# 0006 — 1024-dimension embeddings with cosine distance

`chunks.embedding` is `vector(1024)` with an HNSW index on `vector_cosine_ops`. HNSW needs a fixed dimension, so the size had to be chosen before an embedding provider is wired in. We chose 1024 over 1536 or 3072 (OpenAI `text-embedding-3-*`) because it is the native size of `voyage-code-3`, a model trained for code retrieval. A smaller vector also keeps the index and memory cost down per chunk. We chose cosine distance over inner product or L2 because embedding providers return vectors meant to be compared by angle, and cosine stays correct even if a provider's vectors are not normalized. Switching to a model with a different size requires a new migration that changes the column type and rebuilds the index, plus a full re-embed of every chunk.
