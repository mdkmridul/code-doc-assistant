# 0003 — Hand-rolled Zod config over `@nestjs/config`

API configuration is a Zod schema (`apps/api/src/config/env.schema.ts`) that is validated in `main.ts` before Nest is created. The result is passed in through `ConfigModule.forRoot(config)` and injected with the `APP_CONFIG` token. We chose this over `@nestjs/config` with a Zod `validate` hook. Validating before `NestFactory.create` means a bad environment fails with one clear list of every missing or invalid variable and exit code 1, instead of a stack trace from inside module initialisation. Injected values keep the exact types inferred from the schema, without `ConfigService.get` string keys. The root `.env` is loaded with Node's built-in `process.loadEnvFile`, so no `dotenv` dependency is needed. Every variable is required and has no default, so a missing value can never be hidden by a fallback. `.env.example` must list every key in the schema.
