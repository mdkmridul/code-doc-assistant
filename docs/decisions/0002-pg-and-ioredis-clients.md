# 0002 — `pg` and `ioredis` as infrastructure clients

The API talks to Postgres through `pg` (node-postgres) rather than Prisma, and to Redis through `ioredis` rather than `node-redis`. This step only needs a connection pool that proves the database is reachable at boot. Bringing in Prisma now would mean a schema, a generate step and a migration workflow before any table exists, which goes against the "build only what the step asks" rule. If Prisma is adopted later for migrations or queries, it gets its own ADR and replaces `PostgresService.pool` behind the same ports. We picked `ioredis` because BullMQ, the likely queue for processors, is built on it, so one Redis client covers both caching and jobs. Both clients live in `apps/api/src/infrastructure`, so the domain package never sees them.
