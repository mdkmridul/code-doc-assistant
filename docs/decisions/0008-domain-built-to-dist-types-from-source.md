# 0008 — `@cda/domain` runs from compiled `dist/`, type-checks from `src/`

`packages/domain/package.json` sets `"main": "dist/index.js"` and `"types": "src/index.ts"`. The API's `prebuild`/`prestart*` scripts run `tsc -p tsconfig.build.json` in the domain package, and Jest maps `@cda/domain` to the source. We chose this over pointing `main` at the TypeScript source, over TypeScript `paths` aliases, and over bundling the API with webpack. Node 22 cannot `require()` TypeScript, so a source `main` crashes `node dist/main.js`. `paths` would compile domain files into the API's output and need runtime path rewriting. Webpack changes how the whole API builds just to inline one package. With this split, type-check, lint and tests never need a build step, and the runtime loads plain JavaScript. The catch: `nest start --watch` does not rebuild the domain package, so after changing domain code you restart the API (the `prestart:dev` hook rebuilds it). Root workspaces are listed `packages/*` first so `npm run build` builds the domain before the apps.
